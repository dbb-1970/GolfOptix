# Reports dashboard — 15 November 2026

Routes: /maintenance/reports/ (authenticated, manager-only data), /test-drive/maintenance/reports/ (fictional public demo). Reports is a primary workspace destination and an Operations overview card. Existing Daily work → Reports opens the same renderer. Reports use the authorized Crew snapshot and introduce no new operational storage. Worker financial projections remain excluded; the renderer rejects nonmanagers before building any reports.

## Delivered views
- Overview and Budget status: saved-budget exact-period allowance, actual ledger spend, outstanding estimates, available balance; clickable area and month bars; budget donut; machine filter; source work-order links; full filtered spending CSV.
- Work order status: all incomplete assignments and map/equipment repairs, emergency first, then scheduled date/time. Closure requests remain incomplete. Optional date, status, unassigned and text filters. Opens source tickets; CSV and printing retain the visible filter context.
- Garage & fleet: current machine condition, directly attributed spending, linked incomplete-order counts, click-through to each machine's ledger and recorded downtime.
- Crew workload: scheduled versus actual logged hours, missing-time and unpriced-time disclosure. Work is credited to the recorded labor worker, not a later assignee. Private loaded-rate editing remains accessible.
- Chemicals: receipts/purchase value, approved consumption, measured adjustments, current balances, latest approved actual versus planned dates and pending review; application/source links and export. Corrected usage is not counted twice. Quantities remain per product and unit.
- Fuel: deliveries and purchase value, machine issues and inventory value, measured corrections and current tank balances; fuel types and units remain separate; clickable machine issues and CSV.
- Component failures: confirmed unreversed replacement quantities and related repair-ticket counts with source links. These are not failure rates; population/exposure remain unknown.

## Accounting and data boundaries
Purchases are counted once through GolfBusiness.ledger; issue/consumption values are separate operational measures. Chemical opening balances and measured stock adjustments are not purchases. The receipt classification now requires the explicit `baseline:false` marker saved by the receipt workflow; ambiguous adjustment records are not silently charged as purchases. No stored transactions are rewritten.

Costs without a work-order/machine allocation remain visibly unallocated. Missing prices are not free labor. No opening tank reading or chemical inventory baseline displays as unknown, not an empty tank/store. Current balances use all recorded dates, while flows use report dates. Unknown future costs are not forecast. Custom dates do not compare a partial period against an annual budget allowance. Project financial scope is disclosed; operational views remain course-wide for the reporting dates. Financial data is USD. Transaction dates follow the existing ledger; work-log ledger dates derive from stored ISO timestamps.

No utilization percentage, mileage-based fuel efficiency, failure rate, regulatory-compliance certification or automatic chemical treatment recommendation is inferred. Fleet availability is recorded state; historical downtime depends on saved transitions. Paper print layout and CSV are provided; no scheduled report email or accounting integration is added.

## Usability, demo and verification
Desktop report tabs and phone report selector, persistent workspace navigation, scrollable table hints, date/scope controls, print styling and spreadsheet-safe CSV. Demo samples use canonical domain commands and remain exclusively in Test Drive session state. No real course records, finances or emails were changed.

Walkthrough Reports step updated and translated. Learning library includes a five-step illustrated English/Spanish report guide. Unit checks cover urgent/date ordering, pending closures, purchase/usage separation, drafts/voids through the existing ledger, attribution, immutable input, unknown prices/baselines, chemical corrections and project commitments. Browser QA covers budget→machine→transaction, fuel→machine→issue, chemical purchase/usage, mobile widths and exported mower CSV.
